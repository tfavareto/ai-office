# UI spec — packages/web/src/ui

## Design system
Dark glass panels floating over the world. Tokens (CSS custom properties on `.ao-root`):
- Surfaces: `--bg` rgba(15,20,30,.88), `--bg-solid` rgba(17,22,33,.98), `--bg-soft` rgba(255,255,255,.04),
  `--bg-hover` rgba(255,255,255,.07); lines `--line` rgba(148,163,184,.16), `--line-strong` rgba(148,163,184,.28).
- Text `--text` #e7ecf3, `--muted` #9aa6b8, `--faint` #8a96aa. Brand `--brand` #2f6fed, accent `--accent` #6ea2ff,
  `--accent-soft` rgba(79,134,247,.16).
- Status: working #3ecf8e, waiting #f5b544, shell #38c9d3, idle #8d99ad, done #6ea2ff, error #ef6b6b.
- Radius 12 / 8 px; shadow `0 10px 30px rgba(3,7,15,.35)`; font: system UI stack (Inter if available), 13 px base;
  numbers tabular. Thin line icons (SVG, 1.75 stroke, currentColor) for every button.
- Motion: 150-250 ms ease-out for panels/toasts; respect prefers-reduced-motion.
- Layout: top bar (56 px); left sidebar (320 px, collapsible); right drawer (380 px, slides in); bottom feed (collapsible
  bar, expands to ~200 px); toasts bottom-right above the feed; popovers anchored to their buttons. Panels never cover
  the world entirely; the world camera focuses into the free area (the world API receives insets).
- Narrow screens (< 900 px): sidebar and drawer become overlays with a scrim.

## Brand
Logo: rounded square (brand blue) with a minimal tower/building glyph. Wordmark: "AI Office" ("AI " in text color,
"Office" in accent), 700 weight. Page title "AI Office"; with alerts "(n) AI Office". Favicon from the logo.

## Components
Store (SSE client with reconnection backoff 2 s to 30 s, mock mode via shared demo simulator, message client, history/
transcript fetchers), TopBar, Sidebar, Drawer (AgentView with tabs, RoomView), Feed, Toasts, NotificationCenter,
MessageComposer, PermissionCard, TerminalPanel (read-only), SessionHistory popover, DayDialog, UsageDialog ("Consumo"), BoardDialog, HireDialog, Settings popover, Help
dialog, Inbox popover (rows, bulk bar, confirmation), Splash ("Connecting to the office…"), Connection banner, Empty state ("No open sessions" + how to start +
demo toggle), HoverTip over the world. Preferences persisted in localStorage `ai-office:prefs` (validated on load).

## Task board
`BoardDialog` (modal, key `K`, top-bar button `board`, or a click on the meeting-room whiteboard through `WorldApi.onBoardClick`).
- **Model (pure, `ui/model/`).** `board.ts` turns the snapshot into cards (`buildCards`: tasks of every agent still in the office,
  room then agent order, the "doing…" form while in progress) and into the board (`buildBoard`: filters `{roomId, accountId,
  agentId, onlyActive}`, three columns over all rooms or one lane per room, completed cards sorted by `changedAt` and folded to
  the last `DONE_PER_ROOM` (3) per room unless "See all", main agents without tasks listed apart). `board-moves.ts` builds the
  message of a move (`buildMoveIntent`: start / complete / pause / reopen / resume between columns, `reassign` to another agent,
  `buildAddIntent` for a new task; every text is a `board.msg.*` catalog key) and follows what was asked (`SentMark`,
  `reconcileSent`: a mark disappears when the card changed status, vanished, the new owner lists the task, or after 10 minutes).
  `world/taskBoard.ts` holds what the board and the whiteboard share (who takes part, board order, the summary).
- **State.** `BoardStore` (`ui/board-store.ts`, `AppContext.board`) keeps filters, grouping, the "see all" switch, the sent marks and
  the picked task, so they survive closing the dialog and the language rebuild.
- **Interaction.** Card click selects the agent (camera frames it, tab Summary) and the drawer highlights the task for 6 s. Drag a
  card onto a column, or onto an agent chip of the drop rail that appears while dragging; keyboard: focus a card and press `M`
  (or use its arrow button) for a "Move to…" menu with arrow keys. Every move opens a confirmation sheet with the exact message
  (editable, Cmd/Ctrl+Enter sends) through the regular message client; nothing is sent without it. The "+" of a column (or lane)
  asks for a new task: agent, title, message; the requested task shows as a dashed card until the agent writes it down. Esc closes
  the sheet, then the menu, then the dialog. Narrow screens (< 900 px) stack the columns.
- **Texts.** `board.*` keys of the ui catalogs (pt-BR source); task titles use `taskLabel` (`tm(titleMsg, title)` for demo tasks).

## Hiring an agent
Entry points (all disabled with the local-only hint when the page is not local): an **empty desk** in a project room (the world reports
hover and click through `WorldApi.onDeskClick` and `HoverInfo.desk`, only while `WorldOptions.hireEnabled`; 2D draws a dashed outline with a "+" badge,
3D a glowing quad on the desk plus the badge; the hover tip reads "Free desk"), the **Hire agent** button in the room drawer, the "+" on a room row of the
sidebar (shown on hover/selection) and the "+" next to the sidebar search, the empty-state card and the `H` key.
`HireDialog` (modal, focus trapped, Cmd/Ctrl+Enter submits): project `<select>` (rooms + **New project…**; the room's path under it); for a new project
a path input with live feedback (instant "use the full path" check, then `GET /api/agents/hire/check` debounced 300 ms; messages in the feedback line)
and the recent folders from `/api/sessions` (newest first, without existing rooms); account chips when more than one account (default: the room's
most recent account, else the default account; in demo mode the demo accounts for simulated hires); first task textarea with a counter (turns red over
8000, submit disabled); model and permission-mode selects (with a hint under the mode); a note that it opens in a new terminal window; error line
(`role=alert`) mapped from the server's codes (no terminal, `claude` not found, folder missing, automation permission…). Success closes the dialog and
toasts "Terminal opened in …". The snapshot's `hires` make every tab draw the **placeholder**: the simulation (shared by 2D and 3D) spawns a person that
arrives by the elevator and sits at `deskIndex` (the first free desk when absent), is not selectable, has no wandering and carries the tag "arriving…"
(also with names off). When the hire gets `agentId` the same person is handed over in place (same desk, no second trip): it takes the agent's data, celebrates for a
moment and shows an "I'm here!" bubble; if the hire expires the person leaves. A hire into a folder with no room builds the room first. Placeholders and their
projects exist only inside the simulation; the sidebar, counters and drawer show real agents only.

## Usage dialog (Consumo)
Opened by a usage card (top bar or the "+N" popover rows; the card's account is preselected) or the `U` key. A wide sheet (1080 px, focus trapped, `Esc` closes), with a fixed toolbar and a scrolling body.
- **Toolbar.** Account picker (a radio group: "All" when there are several accounts, then each) and period tabs (Today / Week / Month). Changing either reloads `GET /api/usage/detail`; while open the dialog refreshes every 15 s (every 2 s while indexing).
- **Loading.** "Carregando o consumo..." first; while the server index is still being built a banner reads "Calculando o historico... 42%" with a progress bar, and the numbers already shown can still grow.
- **KPI tiles.** Total tokens (input + output + cache writes), estimated cost, change against the same elapsed part of the previous period (arrow and sign, so not color-only) and cache hit share (cache reads / all input context).
- **Chart.** Inline SVG, no library. Stacked bars of output, input, cache writes (and cache reads, off by default because they dwarf the rest) per hour (today) or day (week, month). `role="group"` with `<title>` and `<desc>` (total, buckets, peak); every bar is focusable (roving tabindex, arrows, Home/End) with an `aria-label` carrying the exact numbers; hover or focus shows a tooltip with exact numbers beside the bar. Colors are tokens (`--usage-input`, `--usage-output`, `--usage-cache-write`, `--usage-cache-read`), the cache types are also hatched or dotted, and a legend names them.
- **Window and forecast.** Per account: the open 5 h block (used, time elapsed and reset countdown, a meter of the use against the reference) and, for the window and the week, the forecast sentences ("At the current pace you reach X by HH:MM (end of the window)", plus "You are likely to reach the limit around HH:MM" when the projection crosses the reference before the window ends), the reference and where it comes from. A note says plainly that plan limits are not visible here and it is an estimate. A collapsible **Limits** form (unit US$ or millions of tokens, per 5 h window and per week) is saved in the preferences (`usageLimits`, per account id) as soon as a field is committed.
- **Tables.** By model, by project and by session or subagent (top 12, "and N more"): tokens, cost and share (bar plus number). People and rooms the office knows are buttons that close the dialog and select them.
- **Card warning.** A card whose projected limit hit is less than 30 minutes away gets an amber ring and a small mark (and the "+N" button when the card is folded into it). The same condition raises one notification per account and window ("Do not disturb" keeps it out of toasts and sounds).
- **Forecast math** (`packages/shared/src/usage/forecast.ts`, pure and tested): pace = mean of the 30-minute and the 60-minute pace (zero when nothing was spent in the last half hour); projection = used + pace x time left; for the week the pace is multiplied by the share of this week's hours with activity (bounded 10-100 %, 50 % early in the week). Reference = configured limit, else the highest completed 5 h block or week of the last 90 days (needs at least 3). Status: no reference, idle, safe, near (80 % or more), will hit, over.

## Day dialog: Time and Report tabs
"My day" (`M`, the calendar button) is one dialog with two tabs in a segmented control (`DayTab`: `time` | `report`, kept in the UI state). `R` opens it on the Report tab; pressing the shortcut of the tab already shown closes it, the other one switches.
- **Time tab.** As before: arrows and a date label, totals per status, one stacked bar per agent.
- **Report tab.** Wide sheet (980 px). Toolbar: a day picker of seven chips (Today, Yesterday, then short weekday and day; a group with `aria-pressed` buttons), **Group by** Project | Agent, the **Include the requests** switch (off every time the dialog opens, with a hint), **Copy Markdown** and **Download .md** (disabled without data). The account is the sidebar filter when exactly one account is selected, else all.
- **Body.** Notices (demo data, usage still indexing, report truncated), seven headline tiles (agents, active time, files with lines, commits, tests with passed / failed in green or red text, tasks, estimated cost with tokens), the day's activity strip (48 half-hour cells, `role="img"` with a text label, tooltips per busy cell, axis at 0/6/12/18/24 h), a highlights box, then sections: per project (strip, agents as cards) or per agent (name, project, cards). A card shows its strip, chips (time span, files, commits, tests, tasks, tokens and cost) and a native `<details>` with files, commits, tests per runner, tasks, tools, commands and the requests (only when asked). Below 900 px everything stacks in one column.
- **Loading.** Today's report reloads every minute while the tab is open; changing the day, the account or the requests switch reloads. A failed load shows the error and **Retry**; a page that is not local gets the local-only hint.
- **Markdown.** `renderReportMarkdown` (pure, in the interface language) writes: title with the date, scope and generation time, summary, highlights, one `##` section per project (agents as `###`) or per agent, and a footer. Session text (task titles, subjects, requests) is escaped; file paths and commands go in code spans. The filename is `ai-office-<date>.md`; the download is a Blob.

## Git section and branch chip
`GitSection` (room drawer, between Accounts and Agents; hidden without `Project.git` or with the **Show Git status** preference off) shows
the branch in monospace with a copy button (and a badge for a detached HEAD or the operation in progress), the changes as chips (files
with conflicts, staged, modified, new; `+n −n` lines), the sync line (`↑ahead ↓behind` arrows with the upstream name, "up to date with
…" or "no upstream"), the last commit (hash, subject, age) and the stash. With a pull request it adds a card: link `#n title` (opens the
pull request in a new tab, `rel="noopener noreferrer"`, only http(s) links survive parsing), state (open, draft, merged, closed), review
decision, a CI badge (green, amber and pulsing unless reduced motion, red) with "n of m checks passed", the failing check names and
the running count. Without a pull request, and with the lookup off on a real (non-demo) local page, a quiet hint explains where to turn
it on. The sidebar room row gets a second line with the branch (ellipsis) and a dot for uncommitted work (red with an operation in
progress); the hover tip adds the branch. Settings has two switches: **Show Git status** (browser preference `showGit`, default on) and
**Look up pull requests with gh (uses the internet)** (server setting, default off; shows why when `gh` is missing or not signed in, and
that it is the only thing that uses the internet). Parsing (`net/parse-git.ts`) validates every field of the snapshot's git state.

## Internationalization
The UI speaks pt-BR (source), en and es. The `language` preference is `auto` (browser languages: pt → pt-BR, es → es,
otherwise en) or a fixed locale, edited in Settings → Language.
- **Catalogs.** `src/i18n/ui/{pt-BR,en,es}.ts` (interface) and `src/i18n/world/{pt-BR,en,es}.ts` (signs, boards, ticker,
  menus, bubbles of the worlds) are flat key → template maps; texts the server and the demo emit live in
  `packages/shared/src/i18n/messages/`. pt-BR defines the key type; en and es are typed against it, so a missing key
  fails `tsc`. Catalog tests check the same keys and placeholders in every language, no empty texts, no shadowed keys
  and no unused keys. **Adding a user-visible string = adding its key to all three locales in the same change.**
- **Templates.** ICU subset: `{name}`, `{n, plural, =0 {…} one {# …} other {# …}}`, `{v, select, a {…} other {…}}`.
- **API.** `t(key, params)` renders a web catalog key; `tm(msg, fallback)` renders a server/demo `Msg {key, params}` (the
  fallback is the pt-BR `text` that travels next to it). Never concatenate translated fragments; use parameters and
  plural forms. Formatters (`ui/format.ts`) use `Intl` for numbers, dates and clocks of the active language; money is
  always USD.
- **Live switch.** `onLocaleChange` makes the App rebuild the UI shell from the current snapshot (selection, open
  panels, scroll positions, focus and camera preserved) and pass `locale` to the world via `WorldOptions.locale`.
- **Not translated.** Text from the user's sessions (prompts, titles, commands, file names), project and agent names,
  the product name.
- **Plugin.** The page sends `locale` with messages and permission decisions (see 02-server and 05-plugins).

## Accessibility
Keyboard shortcuts as in 00-product.md; focus-visible rings; aria labels on icon buttons; live region for
announcements; color is never the only signal (status also has text).

## Inbox
`InboxPopover` is the "need you" counter's popover (`data-popover-trigger="inbox"`, key I). It is the one popover that
stays open while the user clicks elsewhere (Esc, I or the counter close it), and it floats in the free area between
the sidebar and the drawer so it never covers the drawer; under 900 px it is a full-width sheet.

- **Model (pure, `ui/model/`).** `inbox.ts` builds the list from the snapshot and the notifications and orders it
  (kind priority, then age); `inbox-state.ts` holds the seen marks and the first-snapshot baseline; `inbox-bulk.ts`
  plans bulk actions and finds "similar" groups; `permission-pattern.ts` normalizes requests (same tool + same command;
  folder + extension for file tools; host for fetches); the dangerous-request detector (`detectRisk`) lives in
  `packages/shared/src/permission-risk.ts`, shared with the server's approval rules;
  `inbox-selection.ts` and `inbox-keys.ts` are the selection/cursor and keyboard rules. `InboxController` (`ui/`) owns the
  UI state and persists the seen marks in `localStorage` key `ai-office:inbox` (validated on load, pruned after three
  days, never sent anywhere). `InboxActions` answers through `AppContext.decidePermission`, i.e. the same client as the
  permission card, which sends `locale`.
- **Items.** Permission (avatar, name, room color and name, tool chip, summary, expiry countdown, warning badge,
  "N similar" chip, four actions and the deny box), attention (what the agent waits for, plus a note that it is
  answered in the terminal; buttons: open agent, open terminal, mark seen), error and finished. Expired permissions
  stay listed, disabled, with "Expired. Answer in the terminal.", last and excluded from bulk actions.
- **Top bar.** The counter shows open permissions plus unseen attention and errors (the tab title and the live
  announcement still count waiting agents); a green pill shows unseen finished work. The button is never disabled: at
  zero it opens the empty state ("Nothing needs you right now").
- **Keyboard.** Active while the inbox is open and focus is not in a field or in another panel: J/K or arrows move,
  Space selects, A approves (with a selection: opens the bulk confirmation; on a dangerous request it only focuses the
  Approve button), Shift+A approves and remembers the first suggested rule (never for dangerous requests), D opens the
  deny box (Enter confirms, Esc cancels; with a selection: bulk deny confirmation), Enter opens the agent, E marks seen.
  Space and Enter belong to a focused button.

## Approval rules
`RulesDialog` (`DialogId` `rules`, class `ao-dialog--rules`) manages the rules of 02-server.md. Entry points: Settings
→ "Regras de aprovação" → "Gerenciar…", the shield button in the inbox title bar, and "Criar regra…" on the drawer's
permission card and on every permission row of the inbox (all disabled when the page is not local).

- **Model and state.** `ui/model/rules.ts` (pure): the editor form and its conversion to a rule draft, the matcher kinds each
  tool offers, the text key that explains a refusal, log filters. `RulesController` (`ui/`, an `Observable`) owns the
  rules, the log, the editor and the preview; it polls every 5 s while the dialog is open (not while editing) so hit
  counters and the log stay fresh, and stops when the dialog closes. The rule suggestion comes from shared
  `suggestRule`: the tool, the normalized command prefix (`npm test`, `npm run build`, `git status`), a folder glob
  (`src/**`) or the host, scoped to the request's project; a risky request suggests a **deny** rule, a compound command
  an `exact` matcher that the editor then refuses with an explanation. The snapshot leaves the tool input out, so
  `AppContext.openRuleEditor` first fetches `GET /api/permissions/:id`.
- **Rules tab.** One row per rule: effect badge (Aprova/Recusa), tool chip, matcher kind and value (monospace), scope
  ("Todos os projetos", "Projeto loja", account), hits and "último uso", the note, an on/off switch, "Ver registro" (opens
  the log filtered by that rule), "Editar" and "Excluir" with an inline confirmation. Active rules first. The empty
  state is one sentence explaining the feature plus a "Criar uma regra" button.
- **Log tab.** The last 500 auto-decisions, newest first: outcome badge (Aprovou / Recusou / Perguntou), who and where,
  the tool, the command/file/address, the rule that matched, "demo". An `ask` entry says the rule matched but the request
  was risky and why. Filters: outcome, text (subject, agent, tool), rule. "Limpar registro" erases it.
- **Editor.** Effect, tool (free text with the usual tools suggested), matcher kind and value with a per-kind hint,
  project (all or one of the open rooms), account, note, enabled. A live preview ("Esta regra teria respondido N de M
  pedidos de hoje.") refreshes 350 ms after each edit; a refused draft shows the server's explanation instead, and a
  refused save keeps the editor open with the same explanation (`role=alert`). A sticky footer holds Save and Back.
  Esc backs out of the editor before it closes the dialog. Under 900 px the editor is one column.
- **Texts.** Every string has pt-BR/en/es keys (`rules.*`, `announce.rules.*`); the feed line a rule leaves is a shared
  message (`activity.rule.allow` / `activity.rule.deny`).
